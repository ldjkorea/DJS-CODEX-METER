## “배포하면 바로 업데이트창” — 읽기 전용 조사

현재 동작:

- `MainActivity.java:164`: 시작할 때 백그라운드 확인 작업 예약. `onResume():212`에는 릴리스 직접 조회·자동 새 버전 창이 없다.

- `ReleaseUpdateJobService.java:27`: 작업에서 기존 릴리스 클라이언트 호출. 성공/304 캐시는 `UpdatePreferences`에서 새 메타데이터 반영 후 알림을 갱신한다.
- `UpdateNotificationManager.java:33-55`: 자동 확인과 알림 설정이 켜지고 OS 알림이 허용된 경우에 새 버전을 버전당 한 번 알린다. 알림을 실제 게시한 뒤에만 `notified_version`을 기록한다. 앱 내부 자동 팝업과는 다르다.
- 기존 알림의 열기/업데이트 동작은 업데이트 화면으로 연결된다. 실제 Android 설치에는 기존 사용자 동의가 필요하다. 현재 앱 소스·의존성에서 FCM 수신 경로는 발견하지 못했다.

**최소 개선 제안(미구현):** 앱 시작·복귀 때 마지막 확인이 일정 시간 지났으면 기존 릴리스 API를 비동기로 확인하고, 새 버전이 발견되면 버전당 한 번 닫을 수 있는 안내창을 표시한다. 자동 확인 끄기와 채널 설정을 존중하고, 연속 복귀/실패 시 재요청을 제한해야 한다. 필요하면 보이는 동안에만 제한적인 주기 확인을 추가할 수 있다.

이 방법은 “앱을 열거나 복귀했을 때 빠르게 안내”하는 방식이다. **배포한 바로 그 순간 백그라운드 앱에도 창이 뜨는 보장**은 아니다. 후자는 배포 이벤트 전달 인프라와 푸시 정책 검토가 추가로 필요하다. 이번에는 업데이트 코드·서버·푸시·권한·알림 설정을 변경하지 않았다.
