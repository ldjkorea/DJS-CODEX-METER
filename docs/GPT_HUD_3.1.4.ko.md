# GPT HUD 3.1.4 — 시작·복귀 업데이트 안내와 한마디

## 승인과 기준

2026-10-24 사용자가 한마디 로컬 검토본과 시작·복귀 업데이트 안내를 포함한 새 정식 배포를 직접 승인했다. 기준은 공개3.1.3/code90 `2e99535f1497e0ce8644ab73de75f2c05a523a4b`. 완료된 문구 검토본은 부모 커밋 `eeaa51a`에 보존했다. 같은 작업본의 `release/3.1.4`에서 이어간다. phone **3.1.4/code91**, 패키지 `dev.bennett.codexmeter`, 기존 서명을 사용한다.

기존 베타를 재공개하지 않는다. Wear3.1.0·Windows3.1.1과 별도 앱·기존 데이터/자산/복구키는 변경하지 않는다. 새 키·권한·서버·유료 API·Drive 업로드·사용자 폰 설치는 없다. 공개 완료 여부·해시·CI·다운로드 결과는 로컬 최종 배포 폴더의 `release-receipt.json`과 `VERIFICATION.ko.md`가 최종 기록이다.

## 기능

- 홈 Activity의 시작/복귀(`onResume`)에서 자동 확인 설정을 따르는 비동기 확인을 예약한다. 화면 렌더에서 네트워크를 호출하지 않는다.
- 마지막 성공/실패 확인 이후5분 안에는 기존 캐시를 재사용한다. 프로세스 내 경과 시간 제한과 단일 실행/기존 네트워크 잠금으로 반복 복귀·동시 자동 확인의 요청 폭증을 막는다. 명시적 “업데이트 확인”은 기존처럼 사용자가 새 조회를 요청할 수 있다.
- 성공한 최신 메타데이터에 설치 가능한 새 버전이 있으면 **버전당 한 번** 닫을 수 있는 안내를 표시한다. 실제 표시 성공 뒤 별도의 업데이트 설정 키 `foreground_shown_versions`에 버전을 추가한다. 기존 Set을 직접 수정하지 않는다. 닫기·뒤로가기·회전·재시작 뒤 같은 버전은 다시 자동 표시하지 않는다. 업데이트 화면의 수동 진입은 계속 가능하다.
- 화면을 벗어났거나 Activity가 소멸했으면 표시하지 않는다. 채널/설치버전/최신 캐시를 표시 직전 재확인하고 진행 중 로그인도 방해하지 않는다. 조회 실패는 기존 진단 저장만 유지하며 토스트/팝업을 추가하지 않는다.
- “업데이트 보기”는 기존 업데이트 화면을 열 뿐이다. 다운로드와 Android 설치 승인 절차는 기존 방식이며 무인 설치가 아니다.
- 자동 확인을 끄면 새 조회·안내를 하지 않는다. 기존 알림 옵션은 **백그라운드 시스템 알림**이며 설정 문구를 명확히 했다. 이 옵션을 켜거나 알림 권한을 요청하지 않는다. 앱 안 안내는 자동 확인 설정을 따른다.
- 앱이 꺼진 상태의 배포 즉시 푸시가 아니다. 보이는 동안 계속 폴링하는 기능도 추가하지 않았다. 새 안내는3.1.4에 포함되므로 기존3.1.3에 소급 적용되는 기능이 아니며,3.1.4 설치 이후의 새 버전 발견에 적용된다.

## 한마디 검토본

부모 `eeaa51a`의 생산5파일을 바이트 정규화 후 그대로 보존한다. 본문131개 수정/493개 유지,624ID·40팁·기존 숨김/끄기·플랜 검증·동일 상태 안정 표시·최근20문구/5팁 제한을 유지한다. 같은 기존 점수에서만 저자 검토 문구의 선택 확률을 높이며 긴급 그룹은 기존 추첨을 유지한다. 일부/독립 한도 판정 보류를 전체 수집 실패·업데이트 장애로 단정하지 않는다.

Android10 이상 균형 줄바꿈, Android8/9 기존 줄바꿈, 기존 중앙 정렬과 큰 글씨 전문을 유지한다. 상세 문구·2~3줄 폭 추정과 한계는 [로컬 한마디 검토 기록](COACH_BANTER_20261024.ko.md)에 있다. 사용자의 실제 폰 수집 오류 원인은 이번에 재현하지 않았다.

## 배포와 복구

기존 정식 GitHub 경로 `ldjkorea/DJS-GPT-HUD`에 새 태그 `v3.1.4`와 기존 이름 규칙의 APK/체크섬을 게시한다. 공개 API→기존 정식 파서의 새 버전 발견→익명 APK 다운로드→크기/해시/서명/버전을 각각 확인한다. 실제 앱 안 버튼 클릭·Android 설치·사용자 데이터 전후 대조는 미검증이다.

이전3.1.3의 커밋·공개 릴리스·APK와 부모 한마디 검토 커밋을 보존한다. 기존 계정/성장 스키마나 서명키의 교체가 없다. 이전 소스는 복구 기준으로 사용할 수 있으나 **낮은 versionCode의 예전 APK가 새 버전 위에 바로 설치된다는 뜻은 아니다**. 문제가 생기면 데이터를 지우는 대신 기존 코드와 높은 code를 사용하는 후속 수정 배포가 필요하다.
