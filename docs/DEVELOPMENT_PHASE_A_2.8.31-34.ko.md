## 2. 실제 문제와 수정

### 내부 31 — 홈·기록

1. 기록 화면의 두 선택지가 모두 `addTrends()`를 렌더링해 달력과 추세 정보가 중복됐다. **달력 관측 기록 / 추세**로 구분했다. 달력에는 오늘·어제, 달력, 선택 날짜의 짧은 요약과 관측 상세 버튼을 배치한다. 추세에는 기존 기간 선택·비교·고급 차트가 남는다.
2. 날짜 진입 인자가 과거 날짜여도 달력은 현재 월에 머물렀다. 진입 날짜에 맞는 월을 선택한다. 기존 화면 상태/스크롤 저장 경로를 유지한다.
3. 한도 후보가 하나여도 선택 안내와 선택 영역을 노출했다. 한도가 하나면 해당 한도명만 표시하고, 여러 개면 기존 선택기를 유지한다. 사용자가 숨긴 한도를 다시 켜지 않는다.
4. 홈의 초기화 설명에서 같은 절대 시각을 반복했다. 실제 구간과 상대 초기화 카운트다운은 보존하고 중복 문구만 줄였다.
5. AI 문구의 여백과 글자 크기를 조금 줄이고, 결제 기간·경과율·이전 정책 상세를 **결제 상세** 안에 접었다. 결제 기간별 결산 진입은 유지했다.

홈 영역 순서·숨김 설정, 삼족오 휘장·대표 메달·칭호, 주간 사용률·잔여량·새로고침, 수동 저장, 내보내기와 보관/삭제 처리 함수를 바꾸지 않았다. 기존 상세 분석 기능을 삭제하지 않았다.

### 내부 32 — 최초 설정과 선택 안내

- 온보딩 완료 화면과 설정에 **선택 기능 안내**를 추가했다.
- 로그인/사용량 조회를 기본 준비로 설명하며 위젯, PC 작업현황, 업적, 칭호, 구독료, 알림은 선택 진입으로 제공한다.
- PC 없이 기본 앱을 사용할 수 있다. 업적·칭호는 각각 성장 화면의 스위치와 기존 확인 절차를 통해 시작한다.
- 안내를 열거나 닫는 동작은 기능을 활성화하거나 온보딩 완료 상태를 수정하지 않는다. 새로운 반복 팝업이나 완료 여부 저장 키를 추가하지 않았다.
- 기존 로그인 사용자의 온보딩 우회, 완료 후 로그아웃, 신규 설치의 안내 분기를 기존 `OnboardingFlow`로 검증했다.

### 내부 33 — 사용량 근거 표시

- `UsageEvidence`를 추가해 **서버 관측값 / 조회 실패 후 마지막 저장값 / 오래된 관측 / 초기화 시각 경과 / 관측 시각 미확인 / 마지막 응답에 한도 없음**을 구분한다.
- 최근 캐시라도 마지막 조회가 실패했다면 홈과 AI 문구의 상태 안내가 성공한 조회처럼 표시되지 않는다.
- 초기화 예정 시각이 지났어도 새 관측 없이 0%를 만들지 않는다. API에 없는 한도를 생성하지 않는다.
- 모든 한도가 응답에 없을 때 사용자 숨김 설정 탓으로 안내하던 홈의 문구를 수정했다.
- 홈의 출처 안내를 누르면 마지막 관측 시각과 정밀도 설명을 볼 수 있다. 정수 관측의 `.00`/`.000`은 표시 형식이라는 점을 명시한다. 실제 소수값은 기존 자릿수 설정으로만 반올림한다.
- 기존 서버 파서·원본 사용률·잔여량 계산·저장 값·2/3자리 설정·위젯 포맷터는 변경하지 않았다. 이번 작업에서 실제 사용자 계정 서버 응답을 새로 조회한 것은 아니다.

### 내부 34 — 결제 기간 결산

**확인된 결함 두 가지를 수정했다.**

1. `AccountProgress`의 계산 이력 식별값은 결제정보/결산 상태/규칙만 포함했다. 소비량이 달라져도 계산 스냅샷이 추가되지 않았다. 정렬된 정책별 확인 소비량·배정량·참고 환산액을 식별값에 포함한다. 실제 소비가 달라질 때 이력이 추가되고, 같은 자료를 다시 처리하면 이력이 중복 증가하지 않는다.
2. 결제액·통화 수정 후 비동기 재계산 전까지 이전 결산을 새 결제정보와 함께 표시할 수 있었다. `BillingEvidence`로 요금제·기간·통화·금액 일치를 확인한다. 일치하지 않으면 재계산 대기 안내를 표시한다. 이전 결산은 이력에 남는다.

화면에는 **등록 구독료**를 따로 표시한다. 접힌 설명에서 등록 결제액, 공개 참고가격, 한도 활용 기반 참고 환산액을 구분한다. 참고 환산액은 실제 API 비용이나 절약액이 아니다.

기존 `MonthlyLedger` 계산식을 변경하지 않았다. 실제 결제 시작일~종료일, 확인된 소비만 반영하는 방식, 주간 초기화 이후 누적 보존, 경계/공백 처리, 정책별 버킷, 혼합 정책에서 금액 합산 보류, 과거 확정 결산 유지 정책을 기존 회귀와 새 대상 검사로 확인했다. 모든 과거 사용자 기록이 완전하다고 판정하거나 미관측 소비를 복원하지 않았다.

## 3. 데이터와 호환성

- DB 스키마·버전, OAuth/토큰/사용량 API, 패키지, 서명키, Widget Provider와 저장 옵션, RPG ID·XP·평가 규칙, Windows/Tailscale 전송 구조는 변경하지 않았다.
- `MonthlyLedger`, `UsageLedgerDatabase`, `SubscriptionStore`, `AccountSession`, `AppPreferences`는 v30 기준과 동일한 내용임을 검사했다. 기존 보호 파일·카탈로그 검사도 유지했다.
- 새 계산 식별값은 기존 `calculations` 배열을 보존한 채 사용한다. 최초 재처리에서 현재 결산 이력이 한 번 추가될 수 있으나 소비량이나 XP를 추가 지급하는 변경은 아니다. 새 스키마 이관을 요구하지 않는다.
- 결제 변경 이력과 계정별 저장 경로를 유지했다. 통화·요금제·한도 정책이 다르면 임의로 한 금액으로 합산하지 않는다.
- 홈/기록을 보는 것만으로 설정이 바뀌지 않는 것을 격리된 에뮬레이터에서 확인했다. 합성 관측을 직접 갱신하는 테스트 자체의 캐시 변경은 설정 변경과 구분했다.

### 개발 중 발견·수정한 검사 문제

- 기존 소스 검사의 오래된 ‘달력과 추세 동시 렌더’ 조건은 승인된 새 화면 구조에 맞춰 수정하고 실제 클릭 테스트를 추가했다.
- 결산 이력 수정의 역사적 보호 검사는 **검토한 호출 한 줄과 추가 메서드만** 되돌려 비교하는 패치를 추가했다. 과거 fixture/업적 조건/원장 계산식을 느슨하게 바꾸지 않았다.
- QA 재사용 시 이전 예약 조회와 합성 관측의 경과 시간이 화면 검사에 영향을 줬다. 테스트 패키지의 예약 작업을 취소하고 각 사례의 합성 관측을 명시했다. 앱의 실패/신선도 기준을 낮추지 않았다.
- 설정 보존 검사가 테스트 자체가 갱신한 `last_snapshot`까지 설정으로 비교하던 오류를 수정했다. 홈은 해당 직접 갱신 키만 제외하고, 기록·안내 진입은 전체 저장 내용을 비교한다.
- 편집 중 인코딩으로 변한 구분자 `·`를 발견해 UTF-8로 복원했다. 최종 리소스/소스/빌드를 다시 확인했다.

## 7. 미검증·Phase B 주의점

1. 실제 Galaxy의 사용자 DB, 로그인 갱신과 실계정 API, 물리 위젯/AOD/Now Bar/Wear, PC와 Tailscale 실연결은 이번 단계에서 실행하지 않았다. 기존 기능 보존의 근거는 소스 보호와 회귀 검사다.
2. 오류·오프라인·리셋은 대상 데이터/캐시 표시로 검증했다. 실제 통신망 단절, HTTP 장애, Doze·자정·장기 백그라운드 동작을 새로 실측한 것은 아니다.
3. 화면 상태 저장 코드를 보존하고 재진입을 검사했지만, 실제 OS 프로세스 강제 종료·모든 화면 회전 조합과 실사용 설정 전체의 무손실 복원은 별도 기기 검증이 필요하다.
4. 화면 진입 속도·배터리·메모리의 전후 벤치마크를 측정하지 않았다. 새 네트워크 조회·서버·대형 이미지·UI 프레임워크는 추가하지 않았다.
5. 기존 부분 관측은 확인된 최소량이다. 빈 날이나 누락 구간을 0으로 확정하지 않는다. 실제 과거 소비를 복구했다고 말하지 않는다.
