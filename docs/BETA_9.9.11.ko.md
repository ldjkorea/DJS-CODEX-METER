# BETA 9.9.11 구현 정본

기준 HEAD: b69cfbbf2e6d712ffb98471b35a942ed4f15fa6d (베타9.9.10). 사용자는 제안한 화면·자동 추천·날짜별 메달·메달 반응형 한마디의 베타 구현을 승인했다. 이번 작업은 로컬 개발/검증/기존 서명 설치 후보까지이며 새 공개 push/tag/Release는 별도 명시 요청 전 실행하지 않는다. 정식3.1.0/Wear/Windows/인증 계약과 기존 성장 원본을 보존한다. Google Drive 자동 업로드/소스 백업을 실행하지 않는다.

## 구현 순서

1. 독립적인 개인 관측 메달 엔진/계정별 SQLite 원장과 백업 병합: 같은 증거 재시도 중복 방지, KST 날짜/초기화/보정/간격/플랜 변경 분리.
2. 기록 달력/홈 세 카드/성장 자동 추천의 간결한 첫 화면, 상세 버튼으로 기존 기능 연결.
3. 메달 기반 로컬 매운맛 선택, 실제 연결 프롬프트/끄기/숨김 보존, 업적·칭호 색상 강화.
4. JVM/SQLite/동시성/계정 경계/복원/큰 글씨·KO/EN·작은 화면/기존 서명 업데이트 검증. 테스트의 기존 fixture와 실패 증거 보존.

## 규칙

- 현재 XP와 기존 티어 계산은 변경하지 않는다. 새 메달은 XP/필수 승급 조건이 아니다.
- 기존의 정상 사용량 응답 직후에만 자동 기록한다. 수동 조회 버튼 자체·팁 조회/복사·화면 진입은 메달/XP 증거가 아니다. 데모 증거는 별도로 표시한다.
- 주간 창이 있으면 주간, 없으면 제공된 월간/5시간 창 순으로 선택하고 그 기준을 기록한다. 동일 계정/정책/초기화 창/같은 KST 날짜의 정상 관측 차이만 누적한다. 6시간 초과 공백 등 기존 원장 분류상 불확실 구간은 제외한다. 최초 관측을0부터 사용한 값으로 간주하지 않는다.
- 일간 기준은 이전28일 중 같은 정책의 양의 관측일 최근14개 중앙값, 최소7일 필요. 당일 처음 관측 시 기준을 고정한다. 70%/100% 도달 시 은/금, 양의 사용량은 동. 기준 부족은 등급 없는 기록 메달이며 주간/월간의 활동일에는 포함한다. 수치는 개인 관측 패턴 비교이며 절대 작업량/성과/다른 사용자와 동등함을 증명하지 않는다.
- 정책 변경 당일은 추가 등급 계산을 멈추고 기존 획득은 보존한다. 계정 변경은 원장을 분리한다. 초기화/하락/불확실 구간은 증가량으로 지급하지 않는다.
- 주간3/4/5일,월간7/10/14일의 기록을 동/은/금으로 자동 저장한다. 같은 기간은 최고 등급 하나이며 업그레이드해도 지급 기록은 중복되지 않는다. 월간 금1/3회에 연결되는 영구 명예·칭호는 별도 원장에 보존한다.
- 자동 추천은 이번 주/달에 남은 날짜로 달성 가능한 다음 메달을 우선하고, 필요한 날짜가 같으면 마감일이 빠른 쪽을 선택한다. 모두 달성했거나 기간 안에 불가능하면 기존 미달성 업적 중 가까운 목표를 선택한다. 이전 고정 설정은 백업 호환을 위해 보존하되 추천에는 적용하지 않는다.
- 홈: 티어/이름/칭호/레벨·남은 한도 → 이번 주간 사용량 → AI 한마디. 홈 지금 할 일 없음. 기록은 메달 달력, 성장은 자동 추천/메달 요약/도감 진입을 먼저 표시한다.

## 소비자에게 보이는 규칙과 범위

- 새 일간 메달은 설치 전 사용량을 소급해서 만들어내지 않는다. 이 버전의 수집이 켜진 상태에서 정상적으로 관측된 차이부터 쌓인다. 최초7개 양의 관측일은 등급 없는 기록 메달이 될 수 있다.
- 예: 같은 정책의 최근 개인 중앙값이2%p이면 오늘1%p는 동,1.4%p는 은,2%p는 금이다. 기준이0.2%p인 다른 계정은0.1/0.14/0.2%p에서 같은 등급을 받는다. Plus/Pro에 가상의 토큰 환산표를 쓰지 않는다. 기준은 자신의 관측 리듬이며 절대 작업량을 같게 만드는 계산은 아니다.
- 주간은 월요일~일요일 KST, 월간은 달력 월이다. 홈 주간 사용량의 서버 초기화 주기와 구분한다. 일간 금을 여러 개 모아야만 월간 메달을 받는 구조가 아니라, 등급 없는 초기 기록도 포함해 **양의 사용량 변화가 관측된 날짜 수**로 월간 메달을 지급한다.
- 새 명예3개: 달력에 남긴 일곱 날 / 나의 첫 황금달 / 세 달에 새긴 금빛. 새 칭호2개: 금빛 달력을 펼친 {이름} / 세 달의 금빛을 모은 {이름}. 기존 도감37명예/24칭호와 별도 원장이므로 기존 ID·획득·장착은 지우지 않는다.

- 대표: “금메달이라고 키보드까지 금도금되진 않더라. 오늘 쓸 답 하나부터 골라보자.” → 기존 `tip.acceptance`의 완료 기준 프롬프트. “개인 페이스 금메달이다. 이제 한도까지 바닥낼 필요는 없고, 필요한 부분만 마무리하자.” → `tip.scope`.

## 로컬 후보/배포 상태

버전9.9.11/code990011/package `dev.bennett.codexmeter.trial`, 기존 키로 서명된 로컬APK를 `GPT HUD/SOURCE/delivery/beta-9.9.11/local-20261017/GPT-HUD-BETA-9.9.11-LOCAL.apk`에 둔다. 정확한 최종 소스 커밋·바이트 수·SHA256·설치된APK 대조 결과는 같은 폴더 `INSTALL.ko.md`와 `SHA256SUMS.txt`에 기록한다. 소스ZIP/Gitbundle/Drive전달물을 추가하지 않는다.

공개 베타9.9.10·정식latest `v3.1.0`/릴리스ID413263261/main `afc7d0b9749a42c034e7b7c7305cf8a6cd7fd23a`를 유지한다. 새로운 push/tag/Release/사용자기기설치/실계정변경은 실행하지 않았다.9.9.11은 아직 인터넷 자동 업데이트로 발견되지 않는다.

### 실패·수정·남은 제한

- 공통 `android/run-tests.sh`는 기존 ParserSelfTest.testGitHubReleases의 “only complete published releases accepted”에서 실패했다. 베타 선택 계약은 별도140개가 통과하지만 공통 전체 통과로 보고하지 않는다.
- `python android/tests/verify-localization.py`는 기존 베타 OAuthClient와 정식 보호 baseline 차이로 실패했다. 이번 작업은 OAuthClient를 기준b69cfbb와 바이트 단위로 같게 보존했다. baseline/fixture를 갱신해 실패를 숨기지 않았다.
- 첫 native 검사에서 코치 view tag 누락, 영어 검사에서 한국어 메달을 잘못 기대한 설정, 최종 칭호 전환 검사에서 비동기 코치 렌더 완료 전에 버튼을 찾은 대기 문제가 발견됐다. 실제UI연결과 언어 fallback을 확인하고 해당 태그/완료 대기만 보완했다. 실패 로그와 이전 성공 로그를 `android/build/beta9911`에 보존했다.
