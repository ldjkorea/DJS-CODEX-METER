## 원인과 수정

공개9.9.9에서 합성 주간값66.75%를 저장한 뒤 Android 자동 사용량 작업을 강제 실행하자 데모 기본값15%로 실제 저장값과 화면이 바뀌었다. 데모의 자동 확인 OFF는 기존 고정/적응 주기 선택이며 예약 취소를 뜻하지 않아, 데모 진입 전에 남은 작업이 실행됐다. 별도로 백그라운드에서43.25%를 저장해도 홈은 기존67%를 계속 보였다. 두 실패 로그와 실제·기대·저장값은 이전9.9.9 문서의 공개 후 수정 절에 보존했다.

- `TrialDemo`: 데모 진입 시 사용량 예약 취소, 합성 토큰 변경을 기존 worker 요청 잠금 안에서 처리.
- `RefreshScheduler`: 데모의 periodic/short/reset 예약 차단과 기존 예약 취소. 릴리스 업데이트 작업은 보존.
- `UsageRefreshJobService`: 실행 진입과 worker 요청 직전에 데모를 확인하여 이미 예약되거나 계정 전환 중 대기하던 작업을 거부. 실제 계정 예약 경로는 유지.
- `MainActivity`: 화면 시작/중지에 맞춰 저장 snapshot 구독을 등록/해제하고 main Handler에서 중복 갱신을 합침. 통합 한도와 바로 아래 주간 사용량은 같은 snapshot으로 렌더링. 홈 main thread에 네트워크 잠금·DB 이관·전체 이력 계산을 추가하지 않았다.

성장 원본/레벨/XP/획득/장착/보관함, 로그인 저장소, API 계약, 업데이트 설치기, 원장은 변경하지 않았다. 홈은 티어·이름·칭호·레벨/XP·남은5시간/주간 한도 통합 카드 → 이번 주간 사용량 → AI 한마디 순서다. AI문구600/팁40, 편집·추가·수동 교체 제외 및 끄기·숨김 정책 유지. 이번 문구 수정0개, 새 의존성·런타임 AI API 없음.
