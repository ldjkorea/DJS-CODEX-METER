## 내부 2.8.39 — 위젯 갱신

### 확인한 문제와 수정

사용량·작업현황 위젯은 같은 입력에서도 RemoteViews와 Bitmap을 다시 생성했다. 사용량 Provider의 호스트 갱신·활성화는 신선한 저장값이 있어도 즉시 네트워크 작업을 예약했다.

프로세스 내부의 최근 성공 전달 표시 `WidgetRenderCache`를 추가했다. 최근 사용 기준 최대 64개 문자열이며 Bitmap·인증 토큰·디스크 캐시는 보관하지 않는다. 입력이 동일하면 실제 렌더와 전달을 생략한다. 실패한 전달은 캐시에 기록하지 않는다.

비교 입력은 원본 소수점 스냅샷·크레딧·계정 해시·티어·위젯 설정·호스트 크기·언어·글꼴·테마·표시 항목·오류·신선도 등이다. 사용량 표시의 분 단위 시간 변화도 반영한다. 작업현황은 기존 6개 작업 전체 fingerprint와 연결 만료 판단을 그대로 사용한다.

호스트의 `onUpdate`, 크기 변경, 삭제에는 표시 캐시를 무효화한다. 프로세스 재시작 후에는 첫 전달을 생략하지 않는다. 설정이나 저장 포맷을 이관하지 않으며 사용자 디자인 선택을 초기화하지 않는다.

사용량 Provider는 신선도·오류·기본 한도 초기화 시각을 확인해 불필요한 즉시 요청을 피한다. 주기 작업과 수동 새로고침은 유지했다. 작업현황도 신선한 연결이 있으면 호스트 갱신을 이유로 같은 PC 요청을 추가하지 않는다. 기존 작업현황의 비깨움 만료 알람·JobService·Tailscale 인증은 변경하지 않았다.

미리보기는 저장 전 초안과 실제 위젯 조건이 다르므로 무리하게 같은 캐시로 묶지 않았다. 진화형 위젯 및 기타 Provider의 레이아웃도 재작성하지 않았다.

### 실제 측정 범위

기존 에뮬레이터 `emulator-5554`의 격리 QA 패키지에서 동일 조건 12회를 비교했다. 실제 생산 렌더 함수를 사용하되 성공 표시 캐시 경계를 합성 호출로 재현했다. 캡처 저장 시간은 측정에서 제외했다.

| 대상 | 이전 생성 횟수 | 개선 후 | 생성·직렬화 시간, 12회 합계 | 단일 Parcel |
|---|---:|---:|---:|---:|
| 2×1 사용량 미리보기 | 12 | 1 | 131.2739 → 50.0450 ms | 4,440 bytes |
| 작업현황 320×180 | 12 | 1 | 54.3529 → 2.4124 ms | 4,580 bytes |

단일 로컬 배치 결과이며 반복 가능한 고정 성능 보장은 아니다. 사용량 측정은 미리보기 1개 구성이고 실제 Android 12+ responsive 전달의 모든 변형·Binder·런처 비용을 측정한 것은 아니다. 배터리·실제 트래픽·장시간 백그라운드 개선량은 미측정이다. 크기·정밀 사용률 변경에 의한 재생성, 호스트 강제 재전달, 64개 상한은 별도 검증했다.

## 내부 2.8.40 — Samsung/Wear

Samsung 잠금 위젯은 기존 저장 스냅샷에 오류·오래됨이 있어도 그래픽을 현재 값처럼 표시할 수 있었다. 이제 기존 숫자 레이아웃으로 전환해 `저장값 · 관측 시각`과 마지막 확인 잔여량을 표시한다. 하루 이상 오래되면 날짜도 표시한다. 전용 5시간·주간 위젯은 저장값 전환 시에도 자기 한도명·값을 유지한다. 신선한 값의 링·막대·다이얼 디자인과 클릭 경로는 유지했다.

합성 관측 0%·100%에서 2가지 모양 × 4가지 스타일 × 3가지 한도 조합을 Android RemoteViews로 적용·측정했다. 오래된 값 전환과 전용 한도 두 가지도 확인했다. 이 검증은 삼성 런처/잠금화면 호스트에서의 실제 지원 증거가 아니다.

Now Bar의 기존 유한 종료 시각·절전 허용 만료 예약, Wear Tile/Complication의 캐시·신선도 경로를 확인했다. 이 영역은 코드·통신 포맷을 바꾸지 않았다. Wear Release 빌드와 lint는 통과했다. 삼성 비공개 호스트 메타데이터, AOD, Now Bar 실표시, 재부팅·Doze 장시간 유지, Wear 물리 장치는 미검증이다.

## 내부 2.8.41 — 백업·복원

기존 암호화 RPG 백업 v1을 유지했다: PBKDF2-HMAC-SHA256 600,000회, 무작위 Salt 16 bytes, Nonce 12 bytes, AES-256-GCM/128-bit 태그, 인증된 형식 메타데이터. 새 키·새 포맷·DB 스키마를 만들지 않았다.

기존 RPG 저널은 XP·이정표·획득일·구/신 업적 보관함·업적/칭호 독립 시작 상태·최초 시작 시각·OFF/ON 세그먼트·대표 메달 순서·장착 칭호·현재/최고 티어·결제 결산·검증 근거를 보존한다. 이번에는 해당 병합 정책을 변경하지 않고 회귀 검증을 강화했다.

### 수정한 보안 경계

- RPG 아카이브의 금지 필드를 OAuth뿐 아니라 PC 페어링 비밀·원본 프롬프트·명령·대화·소스·개인키로 확장했다. 실제 계정 해시는 복원 계정 검증에 필요한 기존 값이다.
- 아카이브 버전 `1.5`를 정수 `1`로 잘라 수용하지 않도록 정확한 정수 검사로 바꿨다.
- 일반 설정 백업의 **새 인증정보 내보내기를 차단**했다. 저장 전에도 확인해 인증 포함 파일을 쓰지 않는다. 화면에서는 새 기기에서 다시 로그인하도록 안내한다.
- 이전에 만들어진 일반 설정 인증 백업의 명시적 가져오기 경로는 기존 호환성을 위해 유지했다. RPG 복원은 계정 로그인 전체 복원이 아니다. 기존 파일은 민감 정보로 취급해야 한다.

동일 계정·다른 계정·반복 복원·오래된 자료의 단조 병합·손상·잘못된 암호·비밀 필드·4가지 업적/칭호 ON/OFF 조합을 합성 자료로 검사했다. Android 실제 SQLite와 파일 입출력에서도 암호화 round trip, 반복 복원 XP 유지, 칭호 OFF 유지, 다른 계정 거부 후 DB 유지가 통과했다.

별도 휴대폰 교체 복원, 사용자의 실제 DB 복구, 실제 2.8.28/2.8.30 설치본 전체 승계는 미검증이다. 이전 자료의 보관·반복 이관은 합성 역사 자료 테스트이며 실제 사용자 기록을 삭제하거나 재작성하지 않았다.

## 내부 2.8.42 — 인증·업데이트·로그

- `SecureTokenStore.load()`가 복호화 실패 시 저장된 암호문을 삭제하던 동작을 제거했다. 기존 키만 읽고, 읽기 과정에서 새 키를 생성하지 않는다. 불완전한 암호문으로 로그인하지 않으며 명시적 로그아웃 삭제는 유지한다.
- 실패 로그는 비밀값이나 예외 원문 없는 고정 이벤트다. 합성 손상 암호문이 보존되고 원본 암호문 복구 후 다시 해독되는 것을 실제 Android Keystore에서 확인했다. 실제 삼성의 잠금·키 무효화 상황은 재현하지 않았다.
- OAuth PKCE·갱신 응답 병합·네트워크 타임아웃·계정 경계를 기존 소스/JVM 검사로 확인했다. 실제 사용자 OAuth/사용량 API 요청은 하지 않았다.
- 진단 필터는 페어링 비밀·연결코드 `cm1|…`·계정 ID·로컬 경로를 가린다. 기존 Bearer/JWT/이메일/인증 쿼리 필터를 유지했고 정상 공개 HTTPS 링크가 잘못 지워지지 않는 검사도 추가했다.
- APK 준비 시 검증한 SHA-256을 보존하고 설치 직전에 다시 해시·패키지·서명·버전 검사를 수행한다. PackageInstaller로 실제 복사한 바이트도 해시 검증 후에만 commit한다.
- 기존 파일 크기·부분 다운로드·SHA-256·패키지 ID·인증서·증가 versionCode·사용자 설치 승인 정책을 유지한다. 실패 시 세션 포기 경로도 유지한다. 제거·초기화·검증 우회는 추가하지 않았다.

실제 Android PackageManager에서 동일 versionCode 차단, 설치 준비 뒤 변경된 합성 파일을 세션 생성 전에 거부하는 검사를 수행했다. 정상 상위 버전 공개 다운로드→사용자 승인→설치 전체 흐름과 복사 도중 동시 변조는 실제로 실행하지 않았다. 서명 불일치·손상·다운로드 계약은 기존 회귀 테스트 범위다.

발견·해결 과정:

1. 최초 컴파일에서 기존 getter 이름과 checked exception 경로를 잘못 참조했다. 실제 기존 API에 맞춰 수정 후 빌드 통과.
2. 제목 복원 전체 JSON 동일성 검사가 기존 복원의 파생 잠금 상태 초기화를 차이로 잡았다. 엔진이나 보상 조건을 바꾸지 않고, 실제 카운트 기준 필드와 연계 메달 근거를 분리 검증했다. XP 중복/데이터 소실 조건은 유지했다.
3. 에뮬레이터 한 번의 APK 설치가 구체적인 오류 없이 실패했다. 원인 미확인 환경 실패로 기록하며, 삭제·초기화 없이 재시도하여 최종 설치/검사 통과.
4. 캡처 I/O가 측정 시간에 들어가던 테스트를 수정하고 재측정했다. 위 표는 최종 측정만 사용한다.
5. Phone lint는 새 Error 없이 Warning 248개. 이전 246개 대비 신규 2개는 인증 내보내기 차단으로 사용하지 않게 된 기존 안내 문구다. 기존 baseline은 53 Error·111 Warning을 필터링하고 있으며 이번 작업에서 숨기거나 baseline을 갱신하지 않았다. Wear lint XML에는 Error가 없다. 기존 Gradle deprecation과 자바 fixture 경고는 남았다.

증거: `android/build/phase-c-jvm-final.log`, `phase-c-release-final.log`, `phase-c-native/RESULT.txt`, `phase-c-tasks/RESULT.txt`, `phase-c-growth/RESULT.txt`, 각 `captures/`, Phone/Wear lint 보고서. 모두 로컬 산출물이다.
