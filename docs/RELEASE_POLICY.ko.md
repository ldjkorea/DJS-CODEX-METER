# 3.0.0 로컬 통합 및 정리 승인 (2026-10-14)

사용자는 모든 GPT HUD 버전의 내용을 통합한 3.0.0 작성과, 완료 후 이 버전에 연결되지 않은 이전 자료 정리를 요청했다. Phone/Wear code85 및 Windows 3.0.0을 로컬로 빌드·검증한다. 공개 push·태그·Release 및 실물 기기 설치는 이번 요청에 포함되지 않는다. 기존 서명·사용자 데이터·Git 이력·라이선스·회귀 fixture는 통합판 유지 자료다.

# 한국어판 버전·업데이트·배포 정책

## 2.9.3 앱 언어·APK 경량화 배포 승인 (2026-10-13)

사용자가 한국어·영어 선택을 마무리하고 최종 검증 후 공개 배포를 명시했다. Android/Wear 2.9.3/code84로 올리고 기존 서명·패키지·데이터를 유지한다. 기존 자동 업데이트 검증과 Android 설치 확인을 거치는 경로를 사용하고 공개 Release 후 실제 익명 다운로드를 확인한다. 앱 언어는 새 설치 첫 실행 및 설정에서 변경할 수 있고, 기존 설치의 언어 선택은 보존한다. Windows 0.1.10은 변경 없이 제공한다.

## 2.9.2 시작 멈춤 수정본 배포 승인 (2026-10-13)

사용자가 2.9.2/code83 수정본 공개 배포를 명시적으로 승인했다. 2.9.1과 기존 자산을 보존하며, 최종 서명 APK·무결성·같은 코드의 시작 잠금 재현/차단·합성 업데이트 보존 검증 후 새 릴리스로 제공한다. 앱을 열 수 없는 사용자를 위한 직접 APK 링크를 함께 안내한다. Windows 0.1.10은 변경하지 않는다. 실제 사용자 갤럭시 해결 여부는 미검증으로 표시한다.

## 2.9.1 정식 배포 승인 (2026-10-13)

사용자가 2.9.1 버전 정합성·최종 검증 후 정식 배포와 기존 앱 자동 업데이트 수신을 명시적으로 승인했다. Android/Wear는 2.9.1/code82로 맞추고 지정 저장소에 최종 소스와 Tag·Release 한 개를 게시한다. Windows 0.1.10은 변경하지 않고 기존 공개 ZIP을 동일 바이트로 제공한다. 아래 차기 개발 보류 지시는 당시 이력이다. 사용자 데이터·서명·패키지·위젯 설정을 보존하고 실제 설치 승인은 Android가 처리한다. 핵심 검증 실패 시 게시하지 않는다.

## 이전 차기 개발의 승인 범위 (2026-10-13)

실제 공개 기준은 Android/Wear v2.8.51/code81, Windows 0.1.10이다. 아래의 v2.8.30/v2.8.50 정책은 당시 이력으로 보존한다. 차기 안정화·프로필 공유는 독립 로컬 커밋/빌드/검증만 허용한다. 3.0은 타당성 설계, DUEL은 연구 문서만 작성한다. 공개 push/tag/release/서명 APK 배포·운영 데이터 변경은 별도 사용자 승인 전까지 금지한다. 내부 목표 2.9.0/2.9.1을 출시 완료 버전으로 표시하지 않는다.

통합 전 공개 기준: 앱/Wear v2.8.30, versionCode 60. 최종 통합 후보: v2.8.50, versionCode 80 / Windows 0.1.10. 최신 공개 여부는 Release와 최종 보고서에서 확인한다. 이전 공개 APK·Tag·자산은 보존한다.

## 최신 사용자 배포 지시 (2026-10-12)

이 정책은 이전 버전별 자동 배포 지시보다 우선한다.

- v2.8.29: 개발·로컬 커밋·검증만 수행한다. Push·공개 Tag·Release·APK 업로드를 하지 않는다.
- v2.8.30: v2.8.29와 위젯 개선을 통합하고 전체 검증을 통과하면 정식 Release 한 번을 생성한다.
- v2.8.31~v2.8.49: 내부 개발 목표다. 공개 Tag·Release·정식 APK를 배포하지 않는다.
- v2.8.50: 모든 후속 변경을 통합 검증한 뒤 통과 시 정식 Release 한 번을 생성한다.

각 기능은 로컬 커밋으로 보존하고 검증을 생략하지 않는다. 기존 SQLite·RPG 성취·설정·로그인·위젯 연결·서명을 보존한다. 미커밋 작업과 `docs/emblem-concepts/`는 삭제하거나 덮어쓰지 않는다. 유료 API·서버와 Tibo X 자동 수집은 도입하지 않는다. 미검증 사항과 데이터 손실 위험이 있으면 숨기지 않고 배포를 보류한다.

## 공개 조건

1. 저장소 이름·소유자·공개 범위를 확인한다. 지정 저장소는 `ldjkorea/codex-meter-ko` Public이며 원본과 별도로 운영한다.
2. MIT 원본 고지와 제3자 라이선스 원문을 포함한다. Pretendard 출처·패치된 AAR 및 최종 APK 해시 검사를 통과해야 한다.
3. 개인 경로·Drive 전달 링크·실제 토큰·서명키·런타임 DB 및 개발 로그가 소스, Git 이력, 릴리스 파일에 없음을 확인한다.
4. 회귀 검사·한국어 리소스 검사·phone/Wear Release 빌드·lint를 통과하고 남는 경고를 기록한다. 실제 기기·서비스 검증 여부를 별도로 명시한다.
5. 최종 공개 커밋, 버전, 기존 한국어 서명 인증서, APK 해시 및 동봉 라이선스를 확인한다.
6. 승인된 별도 저장소에만 push한다. 원본 저장소에 push하지 않는다.
7. 검증한 APK·SHA256SUMS·라이선스 묶음으로 draft Release를 만들고 검증 후 게시한다. 게시 뒤 비로그인 접근과 실제 자산 다운로드 해시를 확인한다.

## 버전

원본과 한국어판은 독립적으로 운영한다. 한국어판 정식 APK는 versionCode를 이전 정식 버전보다 높이고 앱/Wear 버전을 함께 맞춘다. 공개된 APK의 내용이 바뀌면 새 버전으로 배포한다. 기존 APK를 `--clobber`로 교체하지 않는다.

버전 변경 시 app/Wear Gradle, AppConstants의 VERSION_NAME/VERSION_CODE/User-Agent, build.sh, run-tests.sh 버전 검사, CHANGELOG, 한국어 릴리스 노트를 함께 갱신한다. alpha를 도입할 때는 원본의 같은 versionCode 규칙과 Android 다운그레이드 제한을 먼저 검증한다. 첫 공개는 실기기 검증 범위를 분명히 밝힌 beta prerelease다.

## 서명·업데이트

현재 한국어 APK 인증서 SHA-256:

`6abd39b13e561cd67fa0d76ab79f9f22500cf5378dc60b176bfe18bf0d2f8be3`

인증서 지문은 공개 검증정보이며 개인키나 비밀번호가 아니다. 기존 키와 패키지 `dev.bennett.codexmeter`를 유지한다. 키를 분실해도 자동 재생성하지 않는다. CI 임시 키로 공개 APK를 서명하지 않는다. 원본 영문판과 서명이 달라 덮어쓰기·동시 설치가 불가능할 수 있다.

2.8.8부터 공개 한국어 저장소만 앱 내 업데이트 대상으로 허용한다. 2.8.7 사용자는 이번 버전을 한 번 수동 설치한다. 설치 자동 승인은 없으며, 크기·SHA-256·패키지·고정 인증서·현재 설치본과 동일 서명·증가한 versionCode를 확인한 후 Android 시스템 설치 확인을 요청한다. 기본 확인 주기는 하루이며 알림은 기본 OFF다. 베타 포함 채널은 새 설정의 기본값이며 기존 선택은 유지한다. GitHub 요청에 OAuth/사용량 토큰을 보내지 않는다. 실기기 업데이트와 취소·OEM 알림 동작은 미검증이다. 앱 제거·데이터 초기화·새 키 생성은 업데이트 문제 해결의 기본 절차로 사용하지 않는다.

## 롤백·검증 범위

오류가 생기면 새 배포를 중단하고 릴리스 노트에 상태를 적는다. Android versionCode 제한 때문에 과거 APK를 무조건 덮어쓸 수 없다. 이전 동작을 복원한 새 versionCode로 수정본을 제공하는 방법을 우선 검토한다. 과거 릴리스와 체크섬은 보존한다.

JVM 계산 검사, Android 컴파일, 실제 기기 UI, 기기 내 업데이트, 로그인/API 정상 동작은 서로 다른 검증이다. 릴리스마다 수행한 범위를 명시한다. 현재 실제 기기 검증은 미수행이다.
