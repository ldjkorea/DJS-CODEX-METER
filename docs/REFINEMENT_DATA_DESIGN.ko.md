# GPT HUD 2.8.25 데이터·성장 설계 및 확인 범위

## 확인한 원인

- 계정 성취는 gpt_hud_account_progress.db의 profiles.document에 있고, 기존 설정 이전은 전체 RPG·결제 결산·대표 메달을 함께 복원하지 못했다. Android 자동 백업은 비활성 상태를 유지한다.
- 대표 메달은 계정별 Preference에만 있었다. 새 선택은 같은 계정 SQLite 문서의 future.showcase에 저장하며 기존 선택을 읽는 경로도 보존한다.
- evaluateCertifiedWindow는 운영 갱신에서 호출되지 않았다. 이제 원장 재조정과 토큰 메타데이터 수신에서 실행한다. 기존 service_unknown 날짜를 완전한 서울 날짜로 바꾸지 않는다.
- 요금제 변경 후 현재 요금제 결산만 찾던 홈은 이전 요금제의 같은 진행 중 결제 기간을 별도 단위로 표시한다. 서로 다른 통화·한도 정책을 합산하지 않는다.

## 명시적 성취 백업

기록 → 설정 → 성취 백업·복원. Android SAF의 CreateDocument/OpenDocument로 사용자가 저장 위치와 파일을 선택한다. 새 .gpthud 형식은 AES-256-GCM(128비트 태그), PBKDF2-HMAC-SHA256 600,000회, 매 파일 무작위 16바이트 salt 및 12바이트 nonce를 쓴다. 형식·버전·암호 파라미터는 AAD로 인증한다. 10~256자 암호는 저장하지 않으며 잊으면 복원할 수 없다. 작업은 별도 worker에서 처리한다. 로그인 토큰·비밀번호·원문 대화는 넣지 않는다.

출처: [Android cryptography](https://developer.android.com/privacy-and-security/cryptography), [OWASP PBKDF2 guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [Android document provider](https://developer.android.com/guide/topics/providers/document-provider).

계정 키는 기존 accountId의 SHA-256을 재사용한다. 같은 계정으로 로그인하면 재설치 후에도 키를 재현할 수 있다. 개인 DB에는 접근하지 않았으며 이 검증은 합성 계정으로 수행한다.

암호 검증 후 파일 버전·계정·53개 업적·보상 근거·금액·원장·대표 메달을 모두 검사한다. 문서 복제본에서 병합하고 SQL transaction으로 profiles와 복원 전 recovery를 함께 기록한다. SQL 실패는 rollback한다. 캐시는 원본이 아니며 다시 구축한다. 같은 자료의 XP·관측·결산은 합산하지 않고 ID별 최대 확인값으로 병합한다. 획득일은 더 이른 확인값, 최고 티어는 최대 기록을 보존한다. 현재 명시적 칭호 해제와 기존 대표 메달 선택은 오래된 백업보다 우선한다. 현재 결제액 수정도 우선하며 참고 환산액을 그 결제액으로 다시 계산한다. 모든 결제 수정 이력을 보존한다.

명시적 삭제 floor 이전의 원시 관측을 재유입하지 않는다. 삭제 이전에 생성된 백업의 결산은 보존 prefix로 합쳐 새로 확인된 소비만 추가한다. 손상된 파일을 일부만 복원하지 않는다. DB 스키마 버전 1과 기존 패키지·서명은 유지한다.

## 평가와 성장

운영 강등은 최신 한도 관측(15분), 토큰 자료(24시간), Asia/Seoul·account·complete 증명, 현재 응답에 명시된 연속 30일 자료(0도 명시), 동일 정책의 인증된 7일 구간을 요구한다. 캐시의 미확인 날짜로 현재 응답의 빈 날짜를 메우지 않는다. 조기 리셋·오래된 복원 구간·요금제 변경 직후·API 실패는 보류한다. 2주 저활용은 내부 경고, 3주 연속과 장기 점수 조건이 함께 충족되면 평가당 최대 1단계 강등한다. 최고 기록과 승급 후 2주 보호를 유지한다. 현재 수집기가 완전 범위를 인증하지 않는 경우 실제 계정의 강등은 보류 상태가 정상이다.

상위 승급은 최근 완전 주간 4개와 최근 활동/한도 또는 충분한 최근 토큰 관측을 요구한다. lifetime 총계만으로 상위 등급을 만들지 않는다. 대한민국·세계는 독립된 게임형 추정이며 실제 이용자 순위가 아니다.

기존 XP/레벨 곡선과 일일 상한을 유지한다. milestone-v25:tokens:<threshold> ID로 100만/1천만/1억/10억/100억의 확인된 토큰에 각각 25/75/250/1000/1500 XP를 한 번씩 지급한다. 공식 계정 요약과 로컬 처리 카운터는 더하지 않는다. 이정표는 실제 API 청구·절약액과 관계없다.

기존 53개 업적 ID·조건·XP·최상위 목표는 그대로다. 독립 칭호 10개는 기존 메달, 확인된 활동일과 완전 주간의 복합 조건으로 해금한다. 칭호 해금/장착은 XP를 변경하지 않는다. 기존 53개 연결 칭호도 유지한다. 문양은 카탈로그 위치가 아닌 고정 ID 표에 귀속된다.

## UI와 검증 원칙

고정 300dp 높이를 없애고 2열 카드의 높이를 실제 내용에 맞춘다. 큰 글꼴에서는 자연스러운 세로 배치를 허용한다. 대표 메달은 가로 3열이며 상세는 선택 시 표시한다. 상태 필터를 먼저 보이고 카테고리/정렬은 접는다. 새 칭호는 같은 보관함에 별도 조건으로 표시한다. 효과 OFF/시스템 애니메이션 OFF를 존중하고 과거 이관/복원은 다시 연출하지 않는다.

JVM·실제 SQLite·에뮬레이터 업데이트·화면/SAF·공개 다운로드 검증은 별도 증거로 기록한다. 실제 삼성 기기, 개인 계정 OAuth/API, 개인 DB 복원, 홈 위젯의 실기기 동작은 이 검증으로 대체하지 않는다.
